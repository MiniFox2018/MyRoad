# MyRoad｜学习、实践与成长

> 从零学习，持续实践，形成能力，创造价值。

**定位：个人成长与技术实践主仓库。** 当前主要探索具身智能和人形机器人，同时建设个人科技探索品牌「狐狸未完稿」，逐步积累进入相关行业所需的知识、技能、项目与职业认知。

**原则：任务驱动，不采用按天、按周或固定天数的强制进度表。** 每项任务有明确目标、交付物和验收标准；何时开始、暂停和完成由自己决定。

## 1. 我希望实现什么

1. **专业能力**：从机器人领域初学者出发，系统理解基础理论，并能够独立分析、运行、修改和验证技术项目。
2. **职业发展**：结合安徽合肥的机器人产业生态，持续研究真实岗位与能力要求，探索进入具身智能行业的路径。
3. **个人品牌**：以「狐狸未完稿」记录真实的学习、技术实践、研究与思考，形成长期可信的公开作品。
4. **长期价值**：在技术能力与作品积累之上，逐步探索求职、协作、开源、产品与商业化机会。

**优先级原则：能力增长和实际成果优先，内容质量其次，不以粉丝量、收藏数量和形式上的忙碌代替进步。**

## 3. 技术主线：基础能力 → 机器人软件 → 具身智能

这是一张**能力依赖图**，不是必须逐门学完的课程表。

### 基础能力

- **Python**：语法、数据结构、函数、模块、文件、异常、环境管理、调试与测试。
- **Linux 与工程工具**：文件系统、命令行、权限、进程、Shell、Git、依赖管理和复现。
- **数学**：三角函数、向量、矩阵、坐标变换、微积分、概率与优化；尽量结合实际问题学习。
- **机器学习基础**：数据处理、模型训练与评估，以及必要的 PyTorch 实践。

### 机器人与具身智能

- **机器人系统**：感知、决策、规划、控制、执行与反馈。
- **机器人学基础**：坐标系、正逆运动学、动力学、传感器与控制。
- **软件与仿真**：ROS 2、机器人软件通信、MuJoCo、基础仿真实验。
- **机器人学习**：机器人数据、示教、模仿学习、强化学习、策略评估与 Sim-to-Real。
- **前沿方向**：具身智能模型、VLA、人形机器人系统及其真实场景能力边界。

不把“学完全部基础”作为接触机器人项目的先决条件；但遇到知识缺口时，必须补齐必要原理。

## 4. 候选实践项目

按兴趣、前置知识和实际成果动态选择，不设置日历截止日期。

| 候选项目 | 核心问题 | 要验证的能力 |
| --- | --- | --- |
| 二维双连杆机械臂 | 关节角度怎样决定末端位置？ | Python、三角函数、坐标与运动学 |
| 三维机器人仿真 | 重力、接触和控制如何影响运动？ | MuJoCo、物理直觉、调试与验证 |
| ROS 2 机器人系统 | 软件组件如何通信与协作？ | Linux、节点与消息、系统工程 |
| 机器人数据与模仿学习 | 机器人如何利用示教数据学习动作？ | 数据分析、LeRobot、PyTorch、评估 |
| 可复现综合项目 | 能否解决一个更完整的问题？ | 需求拆解、实现、测试、文档与复现 |

**项目完成不等于代码跑通。** 应尽可能保留源代码、运行说明、实验结果、测试、问题与复盘，成为可用于自我评估和职业展示的证据。

## 5. AI 原生学习与开发方式

采用“**真实问题牵引 + 必要理论 + 动手实验 + 能力验收**”的学习方式。

AI 主要扮演三种角色：

- **教师**：解释概念、拆分难点、设计练习；初学时不一上来就直接给完整答案。
- **结对程序员**：辅助配置、写代码、排错、生成测试和技术方案，提高开发效率。
- **技术面试官**：要求解释程序、预测结果、独立修改代码或处理相似问题，检验是否掌握。

接受 Vibe Coding 的效率优势，但明确区分三个层次：

1. **能运行**：得到预期结果并理解基本流程。
2. **能修改**：解释关键代码，修改参数或功能，定位常见错误。
3. **能迁移**：面对相似新问题能提出方案，合理使用 AI，并验证结果。

机器人仿真与将来的真机控制尤其重视坐标、单位、边界条件、异常情况和安全验证。AI 生成的代码不能未经检查就被视为正确。

## 6. 多设备技术环境（候选方案）

- **MacBook**：日常学习、AI 协作、数学可视化、轻量 Python、技术阅读和内容创作。
- **联想拯救者 + Ubuntu WSL**：主要 Linux 开发环境，逐步承担 ROS 2、MuJoCo、数据处理和 GPU 实验。
- **Git**：跨设备管理源代码与项目历史；确有需要时再配置远程开发。
- **候选技术栈**：Python、NumPy、Matplotlib、pytest、ROS 2、MuJoCo、PyTorch、LeRobot。

版本选择以官方支持、稳定性和项目兼容性为准。Ubuntu 24.04 + ROS 2 Jazzy 是候选组合，**尚未安装或验证**。Isaac Sim / Isaac Lab 等大型环境暂不作为入门前置要求，也不预设 RTX 3080 能运行所有 GPU 训练任务。

坚持“先完成轻量、可验证的实验，再按实际需要增加工具”，避免把时间消耗在工具和环境本身。

## 7. 职业探索：从合肥出发

目前不提前锁定唯一职业。初期优先了解：

- 机器人软件开发、仿真测试与系统集成；
- 机器人数据、模型评估、具身智能应用工程；
- 机器人学习算法（作为更深入的长期方向）；
- 机器人产品、技术解决方案与行业研究。

以**真实岗位要求 + 个人实践表现**校准方向：岗位需要什么，已经有什么作品可证明，还缺少哪些基础。

持续关注合肥的高校、研究机构、机器人企业、产业载体和真实部署场景，同时比较其他地区的产业和就业机会。企业宣传、研究演示、招聘信息都要注明来源与核验时间，不把政策目标或技术展示当作已被证实的实际能力。

## 8. 个人品牌：「狐狸未完稿」

**定位：真实的个人科技探索者。** 当前以具身智能、人形机器人为主要内容，保留 AI 工具、软件实践、独立项目和个人思考的空间。

| 平台 | 内容定位 | 前期适宜形式 |
| --- | --- | --- |
| 微信公众号 | 深度研究、技术解释、系统性分析 | 图文文章 |
| 小红书 | 视觉化科普、概念与知识提炼 | 多页图文 |
| 抖音 | 动态演示、技术解说与实验记录 | 视频或适当的图文 |

三平台已统一品牌名称。采用“**一次可靠研究，多平台差异化表达**”：

选题 → 原始资料核验 → 内容母稿（事实、证据、观点、未解问题）→ 按平台改写和制作 → 质量检查 → 反馈复盘。

不机械地把一篇文章复制三次，也不要求每个主题必须三平台发布。学习成果可以公开，也可以仅保留为私人技术记录。

内容需区分事实、企业主张和个人判断；特别核实机器人是否自主操作、是否遥操作、演示是否剪辑、测试条件及成功率。涉及他人视频、图片和 AI 生成素材时注意授权、归属和必要标识。

## 9. 科研信息入口：从研究发现到实际能力

**当前明确确认的科研信息入口：**

- [Papers with Code](https://paperswithcode.co/)：用于发现与具身智能、机器人学习相关的研究任务、论文、代码线索、模型、数据和评测信息。
  - [Robotics 研究任务](https://paperswithcode.co/tasks/robotics)：Papers with Code 内的机器人专题页面，属于同一来源，不单独算作新增信息源。

**收录边界：** 科研信息源清单以本人明确提供、认可的来源为准。AI自行搜索发现的网站、平台或工具，可用于分析与核验，但默认只是建议，不自动加入正式来源清单。若发现已有信息明显错误、失效或存在重大风险，应先说明事实与依据，再决定如何修正。

**建议使用方式：**

1. 先从具体学习任务或研究问题出发，在 Papers with Code 中寻找研究线索，不把浏览排行榜当作日常强制任务。
2. 对准备学习或公开传播的结论，核实其原始资料、发表时间、方法、实验条件和限制；研究索引不等同于结论已经独立证实。
3. 对值得尝试的项目，核查是否真正公开代码、运行环境、数据、许可及评测方式；“有代码”不意味着一定可复现。
4. 经理解和验证后，再按已有分工归档：系统知识进入 [Study](https://github.com/MiniFox2018/Study)，有持续价值的资源进入 [NoIT](https://github.com/MiniFox2018/NoIT)，实际任务与项目成果进入 MyRoad。
5. 对确实值得分享的研究与实践成果，再考虑转化为「狐狸未完稿」的平台内容；不要求每个主题都发布到三个平台。

**特别注意：** 评测排行需要结合测试任务、数据、指标与条件理解；机器人展示要核实自主与遥操作、剪辑、成功率和真实部署条件。引用、截图和转载须考虑来源、授权和平台规则。

## 10. 动态任务机制

MyRoad **不是打卡日历，也不是待办事项堆积场**。执行时每次优先选择当前最值得做的一项核心任务，完成后依据成果决定下一项。

建议每张任务卡包含：

- **任务**：具体解决什么问题。
- **价值**：为何现在值得做，与学习、职业或品牌有何关系。
- **行动**：必要步骤与可用资料。
- **交付物**：代码、实验、学习笔记、研究结论或公开作品。
- **验收**：如何证明不是“看过”或“AI帮忙做过”，而是真正有进步。
- **后续**：继续、补基础、调整方向或暂停。

**不设人为截止日期。** 可以根据实际兴趣和困难调整任务；有价值的失败实验也应记录，但不能虚报为成功。
 
### 候选的第一类任务（尚未启动）

**理解机器人任务闭环**：选择一段有出处的机器人抓取或取货案例，尝试画出“感知 → 状态判断 → 规划/决策 → 控制 → 执行 → 反馈”的关系。

- **交付物**：一份简洁流程说明，注明案例来源、已经理解的环节与未解问题。
- **验收标准**：能够独立解释每个环节的作用，说明演示表现为何不等于普遍自主能力。
- **后续分支**：根据理解情况，选择 Python 二维机械臂实验、机器人示教数据观察，或合肥企业应用案例研究。

以上仅为候选方向，不代表任务已启动；每次根据实际反馈决定下一项任务。
